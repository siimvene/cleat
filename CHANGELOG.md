# Changelog

Newest first. A line per gate or behavior change; policy changes to this repository's own baselines are in the commits that made them.

## Unreleased

- Layering, fifth pass (fail closed): a name is the import machinery if any binding it may have in its scope is — a dead `if False:` rebinding, a later `del` or reassignment no longer hides `importlib`, a parameter's default and either side of `x if c else y` / `a or b` count, and a name lookup that may miss (a class body binding the name, the module, `exec`'d code) reaches the module and the builtins, never an enclosing function's local, as Python's lookup does; `exec`'d code counts every binding along the calling scope's chain. Aliases are solved as a fixed point, linear in the bindings (three rebindings per name made the old resolver exponential and could stall the gate). `nonlocal` binds in the nearest enclosing function that binds the name; a `global`/`nonlocal` assignment's value is read in the scope it sits in; A file nesting `exec`/`eval` strings deeper than the reader follows is reported unparsed (a failure under `unparseable: "fail"`) instead of passing silently; an `__import__` level deeper than any package names nothing and is refused in constant time. Every symlink the walk meets is judged: a source-file link out of every root that imports nothing in one, and a directory link out of every root (never descended, so nothing under it was judged), are violations (a link to a judged root itself is inside it) named `symlink` at line 0, exempted by the link (`file`) and where it points (`target`); a directory link inside the roots is not descended, its files judged where they really are. Upgrading can surface references the old reader let through, and a tree with an out-of-root directory link fails until it gets an entry.
- Layering, second pass: Python files are parsed from their bytes under their BOM or `coding:` cookie (a utf-7 cookie could hide an import in a comment; a BOM or latin-1 cookie made the parser fail over to the regexes silently). A file that still does not parse is read statement by statement and named on a WARN line, a failure under `layering.unparseable: "fail"`. Dynamic imports are read by keyword, with `package` (it wins over the caller's location) and `fromlist`, through aliases, `getattr` of a constant, constant concatenation, `exec` of a constant and `runpy.run_module`; only importlib's/builtins'/runpy's own functions count, not any method sharing the name. Under `unknown_layers: "deny"` an `always_allowed` layer missing from `allowed` is confined too, so it cannot relay (list it in `allowed`, null for unrestricted). Layers come from a file's real path, so a symlink cannot relay; a symlink out of every judged root is a violation. A malformed exemption is the config diagnostic (exit 2), not a traceback.
- Layering: an `exempt` entry may name its `target` (the referenced file, as the failure line prints it) and then covers that reference only; without one it matches by file and name as before, so `from app.billing import x` no longer rides on an entry written for `models/billing.py` once entries carry targets. The failure prints each violation as a ready-to-paste entry, target included. `layering.unknown_layers: "deny"` confines a layer `allowed` does not list to itself and `always_allowed` (default `"allow"`, unchanged). Python imports are read with `ast`: comma lists, semicolons, backslash continuations, `__import__`/`importlib.import_module` of a constant, and `from pkg import submodule` (resolved to the submodule, also in a package without `__init__.py`) are now references; a file that does not parse falls back to the regexes. Upgrading a Python project can surface references the regexes missed, and retire exemptions a regex matched in a docstring.
- Complexity `--changed`/`--only` judges only the changed files that fall within the gate's configured `sources`. A changed file outside them — vendored `quality/` tooling in a consuming project, say — is no longer measured just because it changed, matching the full scan (and how escapes/conventions already restrict to their scope).
- Duplication: `sources()` lists files with `git ls-files` (tracked or not ignored) inside a git work tree, falling back to the directory walk otherwise, so a git-ignored build artifact or generated copy is no longer scanned as a clone.
- Duplication: import declarations are not significant lines, so a linter that forbids wildcard imports no longer makes every file's identical import list a clone the ratchet holds forever. The prefixes are per-language (`import`/`from` in Python, `use` in Rust, `require`/`require_relative`/`load` in Ruby, `import`/`package` in Kotlin/Java/Go, `import` only in Swift and TS/JS), so Swift's `package` access modifier and Ruby's `use` middleware stay counted. A repo with import-block false clones drops sharply; upgrading an existing project shifts its density (imports leave the denominator), so re-baseline duplication after refreshing. Single-line declarations only: a multi-line `import (` block still clones on its inner lines, and the density excludes import lines whatever the backend, but the built-in finder is what skips them from clone detection (jscpd users configure jscpd's own ignores).
- The Stop hook reports a failure set once: the report that blocked is fingerprinted under `quality/.running/`, and a later stop that would send the identical report gets one line and exit 0 rather than the whole report again. On the pilot codebase a failure the agent could not fix (a policy question for a person) blocked every stop and re-sent the same report eight times in one session. Any change in any gate's output — a file fixed, a file broken, a count moved — is a new report and blocks again. `--stats` renames the row this feeds from "blocked twice in a row" to "report already sent", which is what it now counts.
- New gates: conventions (a project's own rules as regexes with a message at the site, ratcheted by site) and dead-symbols (declared names nothing references, through ast-grep; a report by default).
- `gate.py --changed` scopes complexity, escapes, conventions and duplication to the files changed against the base; the Stop hook attach writes uses it, CI still runs everything.
- Mutation: a filtered (narrow) suite run that executed no tests is inconclusive, not survival; the full suite decides. It made CI flaky on Linux, where the filter sometimes matched nothing.
- #3: identical `(file, text)` findings are matched by the values they still share with an entry, then by nearest recorded line (entries now record their line), so a function inserted between two baselined twins is the new one, not a neighbour.
- #4: the Rust test skip is the `#[cfg(test)]` item's own braces, not the rest of the file; production code appended below the test module is judged by complexity, escapes and duplication.
- Ratchet: two baselined findings in one file with an identical declaration line (`def check(` twice) no longer collide on the baseline key and compare against each other, which failed the gate on an unedited tree. Matched by occurrence order within the file (#1, #2, by @michaeldtimpe). Insertions between them are tracked in #3.
- Escapes: `fixtures` joins the default skip directories (#2).
- Every hook and guard firing is one line in `quality/.events.jsonl`; `gate.py --stats [--since 7d]` reports firings, fail rate, fixes after the hook fed a failure back, and what the guard refused while a gate was red. An allowed call records only the tool, never the command; `"events": false` turns the log off. Attach gitignores it.
- The mark: `assets/cleat-mark.svg` and a one-ink `assets/cleat-icon.svg`.
- Attach is local by default; `--ci` adds the workflow, CODEOWNERS and prints the ruleset command. `--git-hooks` writes a pre-push hook. `--refresh` upgrades a vendored copy and migrates the retired complexity shape; `--add` merges the gates a config lacks.
- The Stop hook blocks one stop, not every stop: on `stop_hook_active` the failures are reported and the agent may stop.
- New gates: manifests (a generated project must name every source), inventory (a directory that must not shrink), public-api (a recorded surface must not lose a signature), sarif, doc-citations, reachability, duplication, changed-coverage, escapes.
- Layering and reachability read imports for Python, TypeScript, Rust, Go, Kotlin and Java, or a parser through ast-grep for nine languages.
- Coverage readers take a `path_map` and refuse loudly a report that names no file under the root. xccov notes the Swift-package files it drops.
- Escapes and duplication skip inline `#[cfg(test)]` modules, as complexity did. Reachability takes `exclude` globs. A bare filename in a citation resolves when unique.
- `gate.py --skip-missing-tools` reports a gate whose tool is absent instead of failing it. `--refresh` refuses while a gate or suite is running from the copy.
- Retired: `check-complexity.sh`, `check-complexity-lizard.py`, `lizard_reader.py`, `check-features-map.py`. One `check-complexity.py` reads with lizard or SwiftLint.
- The engine: `ratchet.py` with five outcomes (new, worsened, held, improved, stale), provenance on every baseline, `--strict`. A baselined function that gets worse fails. Failures never print the command that accepts debt.
- `attach.py`: one command to attach, with baselines written so day one is green.
- Conformance fixtures for nine languages; a shared test harness.
- No references to other projects anywhere in the tree.
